## Project Config
<!-- slug: project-config | kind: domain | title: Project Config -->
- Owner decision (2026-10-24): an unknown key at any level of wsx.config.yml is ignored with a warning, never an error. No strict mode, no typo matching. Known keys with a wrong type or value still fail.
- Why: lands run the installed (older) wsx; a land that added a key (tasks.workflow.idle, tasks.env) made the installed wsx refuse the file, so auto-deploy and every later land/ledger/task new failed until a hand deploy (three times on 2026-10-24).
- How: crates/wsx-core/src/config/project.rs parse_yaml wraps yaml_serde::Deserializer in serde_ignored::deserialize (dep pinned =0.1.14, only dep serde_core) and puts one line into ProjectConfig.notice naming the file and up to 8 key paths. load_task_config prints it to stderr once per process (warn_once); load_project_config keeps it as the TUI project notice (never stderr: the TUI owns the screen).
- Other config files (web site file crates/wsx-web/src/site.rs, themes) still refuse unknown fields on purpose: they are trust boundaries.
