## Web Client Chat Reading
<!-- slug: web-client-chat-reading | kind: coding | title: Web Client Chat Reading -->
- `useFollowEnd(name, ready)` in `web/lib.js` owns opening: per-chat `{read, place}` in localStorage `wsx-read` (200 newest). Rows are log children with `data-key`, `data-in` + `data-at` (replies). A reply is read when its bottom was on a visible screen.
- The hook's observers capture the first render's closures: props must go through refs (`loaded.current = ready`).
- The "New" row (`.log-new`) must be spliced into the keyed row array (`withNewLine` in chat.js); returning two roots per mapped item makes unkeyed fragments and remounts rows.
- Opening at the New line needs content tall enough below it; a reply whose diagram draws late is short at placement, so the browser test uses TABLE5 (table + 30 lines) in `scripts/fake-claude-stream.py`.
- Replies: `web/reply.js` (new asset, listed in `src/assets.rs`). Delegated pointer handlers on `.log` read `data-quote`; touch rows get `touch-action: pan-y` and no text selection, so the menu has Copy.
- Tables on a phone: `data-fold` (>3 columns) turns the table into one grid with subgrid rows; extra cells go to column 2 with `data-head` via `::before`. The session markdown fixture's 6-column table now fits on a phone (test expects no sideways scroll there).
- `readMap`/`writeMap` moved from store.js to lib.js (store imports lib; lib cannot import store).
