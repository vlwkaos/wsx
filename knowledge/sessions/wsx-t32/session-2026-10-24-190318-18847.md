## Task Check Slot
<!-- slug: task-check-slot | kind: coding | title: Task Check Slot -->
- Owner: `crates/wsx/src/task/slot.rs`; contract in docs/tasks.md "Checks, revisions and report" (**Check slot**).
- Slot = `flock` on `$XDG_STATE_HOME/wsx/tasks/check-slot/slot.lock`; the kernel frees it with the process, so a killed host never blocks.
- Queue = ticket files `q-<prio>-<ms>-<pid>-<seq>`, each kept locked by its waiter; created as a dot file, locked, then renamed so no one prunes a new ticket. A ticket whose lock is free is a dead waiter's and is removed.
- Order: name sort. Priority 0 = checks after a landing's rebase; 1 = everything else (ready gate, trial, worker's full check-run).
- A worker's check-run of only plain `cargo fmt|build|check` commands skips the slot (`host.rs` `light`).
- Visible: record `waiting {on: check_slot}` while state stays `checking`/`working`; log `check_queued{reason}`. `set_state` clears `waiting` for any non-waiting state, so set it after `set_state(Checking)`.
- Timeout counts from the slot: the slot is taken in the check thread before `run_check`.
- The broker client has no read timeout for `check-run` (queue + checks can pass 15 min).
- Host field `check_run`: a repeat worker check-run of the same checks joins the running one (all callers get one answer); other checks are refused until it ends. Proven by fake word CHECKRUN_AGAIN in test-task.py 32b.
- test-task.py uses its own XDG_STATE_HOME, so its queue never meets the real host's (no deadlock when the gate runs it).
