## macOS Socket Calls After The Peer Closed
<!-- slug: macos-socket-after-peer-close | kind: coding | title: macOS Socket Calls After The Peer Closed -->
- A Unix-socket server that answers on the request's newline may close before the client finishes. macOS then fails the client's `set_read_timeout` (EINVAL) and `shutdown(Write)` (ENOTCONN), though the answer is buffered and readable.
- Fix in the client: ignore EINVAL from a per-read timeout and NotConnected from shutdown, then read. Done in `vendor/asched/.../routine/ipc.rs`; wsx-core `client.rs` has the same rule for terminal streams.
- Proof it is not a dropped connection: on the failure the daemon was alive, same socket, an immediate retry answered.

## Reproducing Flaky Checks From A Task Worker
<!-- slug: flaky-test-reproduction | kind: coding | title: Reproducing Flaky Checks From A Task Worker -->
- The worker sandbox cannot open sockets or PTYs, and `WSX_TASK_BROKER` makes `wsx` refuse non-task commands (unset it for local runs).
- `wsx task check-run 6` runs `scripts/runtime-smoke.py` from the working copy outside the sandbox, without forwarding env. A temporary stub there that execs a stress script under `.work/` gives a real reproduction loop; restore it before committing.
- 16 parallel test-binary runs plus one `cargo nextest --workspace` reproduced the routine flake about 1 in 100; 8 parallel without load did not.
- `until(expr, label, n)` in `scripts/web-cdp.mjs` counts attempts of 100 ms, not seconds. `go(hash)` only sets the hash: wait for the next view before touching state the old view writes on unmount.
- A routine test with cron `* * * * *` races its own manual run at a minute boundary; use a date that never comes (`0 0 31 2 *`).
- Vendored asched lib tests have 2 deterministic failures (SUN_LEN path, retirement lock) that are not in the gate.
